Backup exercise

Try this before close only if time remains. It appears after playback and scorecard as a reference section, not as an extra time slot; playback stays at 17:10–17:30. Use the common scorecard.

Objective

Compare usefulness by changing one variable, not by declaring a symbolic winner.

Input
Your logged Exercise 5 run, its starting commit and request
Best use
Optional parallel or waiting-time task before close
Roles (suggested)
Auditor / observer with the agent operator

Steps

  1. Choose one comparison: two models, HVE Core versus HVE-Squad, or HVE versus another harness (your own orchestrator or plain Copilot agent mode).

  2. Use Exercise 5 as Run A. Run B repeats the same item, request and definition of done from the same commit, with one variable changed.

  3. Compare time to first useful output and accepted outcome; count questions, corrections, approvals, retries and unplanned interventions.

  4. Review consumption or available cost signals alongside quality and rework, including failed and abandoned runs.

  5. Identify a reusable improvement and write a recommendation by phase and context.

Hand in

Tick items as your team hands them in.

Exercise 10 · How to start

Change one thing, measure everything

Start here

  1. 1

    Choose one comparison: two models, HVE Core versus HVE-Squad, or HVE versus another harness.

  2. 2

    Run A is usually your Exercise 5 run, already logged. Run B re-runs the same item with only that change.

  3. 3

    Start Run B from the same commit and request. Short on time? Compare research and plan only on both sides.

  4. 4

    Fill the comparison sheet as you go, then write the recommendation: phase, context, approach, reason.

Tips and tricks

  • Another harness can be your own orchestrator or plain GitHub Copilot agent mode without HVE.
  • Time: note the start, the first useful output and the accepted outcome. Count every question and correction.
  • Cost: HVE-Squad’s consumption.md per dispatch; GitHub Copilot usage metrics and AI credits for the rest.
  • Two teams ran different approaches on similar items? Compare across teams instead of re-running.

Watch out

  • Changing the model and the harness at once
  • Comparing a full run with a partial one
  • Declaring a winner instead of a phase and a context

Where the numbers come from

the auditor’s log · HVE-Squad consumption.md (model, tokens and estimated cost per dispatch) and decisions.md · HVE Core research, plan, change and review files · GitHub Copilot usage metrics and AI-credit consumption

Cross-team comparison is observational

Similar items from different teams can reveal useful patterns, but they do not isolate one variable. Record the differences in scope and context; do not present this as a controlled same-commit re-run.

Done when

Tips

  • Use logs and state files, not memory.
  • Cheaper models can cost more if they need more cycles; hold the harness fixed when comparing models, and hold the model fixed when comparing harnesses.
  • Measure cost per accepted outcome, not tokens per run.
  • Reuse your Exercise 1 answer sheet to compare predicted and actual human decisions, and the PO edit log from Intermission A.
