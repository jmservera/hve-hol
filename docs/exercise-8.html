Exercise 8 · Open lab 4 · Core task

Cross-team red team and recovery drill

Core taskOpen lab 4

On this pageBriefHand-in and toolkitTips
Objective

Test whether the process is robust when challenged, interrupted or partially wrong.

Input
Another team’s outputs
Best use
Core task
Roles
Whole team, paired with another team

Steps

  1. Exchange artefacts, not verbal explanations.

  2. Challenge missing context, security, testability, operational readiness and traceability.

  3. Inject one failure: missing project ID, tool error, incomplete experiment, stale context or rejected assumption.

  4. The original team recovers without silently discarding the evidence chain.

  5. Record which faults were caught by controls, by agents or by people.

Hand in

Tick items as your team hands them in.

Exercise 8 · Hand-in and toolkit

Challenge with artefacts, recover with evidence

Five lenses

  • Context

    What is missing, stale or unsourced?

  • Security

    Data, secrets, permissions, sensitive content?

  • Testability

    Can every acceptance criterion be tested?

  • Operational readiness

    Rollback, runbook, monitoring, hand-off?

  • Traceability

    Evidence → decision → requirement → plan → result?

Fault cards (draw one)

  • Missing project ID
  • Tool error
  • Incomplete experiment
  • Stale context
  • Rejected assumption

Template cells are editable: type in them, then use Copy as Markdown to paste the result into your repository or wiki. What you type stays in this browser only; nothing is uploaded.

Recovery log

FaultCaught by (control · agent · person)DecisionRouted to (research · plan · implement · new item)Evidence kept

Recovery rules: record the fault and the decision · route it to the earliest responsible phase · never delete evidence to make the story look clean

Run it with

  • HVE Core: the Code Review agent and /rpi-review compare the work with the requirements and plan, read-only; /rpi-challenger tests the assumptions.
  • HVE-Squad: team state and the append-only decisions log live in the repository, so a team can resume after an interruption and show who decided what.

Links

  • HVE Core · RPI workflow (opens in a new tab)
  • HVE Core · Security planning (opens in a new tab)
Done when

Each team can show the fault, who or what caught it, and the evidence chain still intact after recovery.

Tips

  • Pairing: A with B, C with D; with five teams, rotate (A reviews B, B reviews C … E reviews A).
  • The facilitators hand out the five fault cards. The red team may not explain the fault; the original team must discover and handle it.
  • Count the “caught by” tally at the end: it is a strong input for Exercise 9 and for the adoption canvas (which controls are worth automating).
