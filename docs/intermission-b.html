Intermission B · While Exercise 6 executes · Open lab 3 · Parallel task

Close the loop: from Azure SRE Agent issue or ticket to patch

Waiting-time taskOpen lab 3

On this pageBriefHand-in and toolkitTips
Objective

Route issues auto-generated by the Azure SRE Agent, or raised as customer tickets, into an automated, knowledge-grounded patch flow.

Input
Azure SRE Agent issues or customer tickets, Ex 6 review; instructions, skills, ADRs
Best use
Waiting-time task during Ex 6
Roles (suggested)
Agent operator and architect; quality lead owns the human gate

Steps

  1. Pick three issues: auto-raised by the Azure SRE Agent, or customer tickets.

  2. Draft a label-triggered workflow: a GitHub agentic workflow, or Jenkins/Bamboo on Bitbucket Data Center.

  3. Ground each patch in knowledge: instructions, skills and ADRs, plus Jira and Confluence via Atlassian MCP.

  4. The agent opens a draft pull request with patch, tests and issue link; a human reviews, never auto-merge.

  5. Feed the outcome back: close, reopen, or turn the failure into a new instruction or skill.

Tips

  • Teams on GitHub use an agentic workflow or Actions to hand labelled issues to the Copilot coding agent.
  • Teams on Bitbucket Data Center (on-prem) sketch the equivalent Jenkins or Bamboo job calling an agent CLI, and write the Jira update back through the Atlassian MCP server.
  • Keep the loop bounded: draft PRs only, a retry limit, and a human merge.
  • The trigger can be an issue generated automatically by the Azure SRE Agent from operational signals, or a ticket raised by a customer; the downstream flow is identical.
