How you run it

Same deliverables, your choice of runtime

On this pageMicrosoft toolchainQuick referenceSetup pins

HVE Core

The toolkit you drive

  • RPI Agent, or the four phase skills: research, plan, implement, review
  • Specialist agents for requirements, architecture decisions, security and Responsible AI planning, a Design Thinking coach, and a Backlog Manager for the Azure DevOps and GitHub paths
  • You approve each phase

Best forlearning the method, one team, tight control

HVE-Squad

Experimental

Orchestration on the same spine

  • One request: a coordinator routes it to a cast of HVE Core agents
  • Autonomy modes: interactive (default) · autonomous · autopilot
  • Cost ceiling, decisions log and consumption ledger
  • Always stops before anything irreversible: deploy, push, merge, schema change

Best formulti-role work, an audit trail, cost visibility per run

Your own orchestrator

Bring what you already use

  • Welcome, if it shows the same evidence: research and plan before implementation, a review record and a decision log
  • Scored on the same common scorecard

HVE is the operating model. The toolkit is optional; the evidence is not.

Tips

  • HVE-Squad is a community project built on HVE Core, at design-partner stage.

Microsoft-first workshop paths

Delivery in Azure DevOps or GitHub; evidence from Microsoft 365

NeedMicrosoft productsBoundary
Plan workAzure DevOps (ADO): Azure Boards work items, or GitHub IssuesRead first; approve backlog writes and the target project/repository
Code, review and CIGitHub repositories, pull requests and Actions; Azure Repos and Azure Pipelines are alternativesNamed reviewers, required checks and a human merge/release decision
Gather business contextApproved SharePoint documents and Microsoft Teams notes/messages through optional Work IQ MCPRead-only source retrieval for this workshop; retain citations, dates and access constraints

Work IQ is optional, not assumed

Use a documented Copilot CLI connection or a workshop-approved MCP-capable client. Before live retrieval, confirm sign-in/consent, tenant policy and available read tools. Preview retrieve may also require Work IQ API billing and a Copilot Credits spending policy. Do not change tenant policy during an exercise. If unavailable or denied, stop that retrieval and use the fictional starting evidence or another approved source pack; record the limitation, never fabricate a live result.

Quick reference

Entry points, and where the evidence lives

HVE Core

VS Code with GitHub Copilot Chat, or Copilot CLI

  • Agent picker → RPI Agent: describe the task; manual by default, full auto only on request
  • Phase skills → /rpi-research · /rpi-plan · /rpi-implement · /rpi-review
  • Before acting → /rpi-challenger (expose assumptions) · /rpi-walkthrough (explain code before changing it)
  • Specialist agents → BRD Builder · PRD Builder · ADR Creator · Security Planner · RAI Planner · DT Coach · Backlog Manager · Code Review
  • Backlog skills → /backlog-plan (read-only) · /backlog-execute (writes to the tracker)
  • Build your own → /hve-builder

HVE-Squad

  • /squad init → review and confirm the proposed team (no autopilot on setup)
  • /squad request="…" → interactive by default; add mode=autonomous or mode=autopilot
  • add cost-ceiling=<USD> → spend forecast and a stop point
  • add routing=off | ranked | economy | manual → model choice per role
  • ask the coordinator to run squad-doctor before work starts
  • /squad-governance-report → governance dashboard
  • Copilot CLI or app: choose Squad Coordinator and send the same text without /squad

Where the evidence lives

.copilot-tracking/
├── research/   ← research notes
├── plans/      ← plan
│               (+ critique in reviews/plans/)
├── changes/    ← change log
├── reviews/    ← review records
└── squad/      ← HVE-Squad state
    ├── team.md · routing.md
    ├── decisions.md
    ├── history/
    ├── consumption.md
    └── state.json

Working memory is not the source of truth: promote decisions to ADRs, requirements, docs and the backlog, and keep .copilot-tracking/ out of main.

Tips

  • HVE Core no longer ships prompt files: /rpi is retired, so use the RPI Agent and describe the task.
  • Use the Backlog Manager for the Azure DevOps or GitHub path; confirm the target organisation, project or repository before allowing writes.
  • The Meeting Analyst agent is experimental and needs the Work IQ MCP server, which may not be available in your organisation. Keep meeting evidence optional: use approved fictional excerpts or the PRD Builder’s questions if live retrieval is not enabled. Teams notes are evidence, not automatic requirements approval.
  • For HVE-Squad, use a fixed, strong model for the coordinator, not Auto.

Setup

Pins for the day

  • HVE Core: record the extension or plugin version installed for the workshop
  • HVE-Squad: one pinned release tag for everyone (v0.18.1 at the time of writing; check Releases)
  • APM CLI: exactly 0.29.0 (0.29.1 and 0.30.0 break the HVE-Squad install); the VS Code route for HVE-Squad needs it
  • PowerShell 7+ on every laptop
  • GitHub authenticated before installing (gh auth login or GITHUB_TOKEN) to avoid rate limits
  • Do not install the official HVE Core plugin next to the HVE-Squad plugin pair: every agent would exist twice
  • One fixed coordinator model for all teams, not Auto

Do not upgrade on the day

Use the versions installed during preparation. HVE Core and HVE-Squad change quickly.
