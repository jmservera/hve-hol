Exercise 4 · Open lab 2 · Core task

From intake to an approved backlog

Core taskOpen lab 2

On this pageBriefHow to startHand-in and toolkitTips
Objective

Experience the human-owned transitions from evidence to build-ready work.

Input
A small greenfield, brownfield or AMS change
Best use
Core task
Roles (suggested)
Product owner decides; agent operator runs; quality lead writes acceptance criteria

Steps

  1. Run intake and requirements clarification.

  2. Generate or refine the business and product requirements (BRD / PRD), in your organisation’s own terms and templates where possible.

  3. Stop at unresolved questions: the product owner decides, defers or rejects.

  4. Create Azure Boards work items or GitHub Issues with acceptance criteria and links to the approved source evidence.

  5. Check whether the backlog preserves intent rather than merely decomposing text.

Hand in

Tick items as your team hands them in.

While your Exercise 4 agents run

The product owner and agent operator can pick up Intermission A: give the product owner a canvas into the HVE loop.

Exercise 4 · How to start

The product owner sits next to the agent

Start here

  1. 1

    Product owner and agent operator sit together with the evidence map and the clarification questions.

  2. 2

    Start the BRD Builder, or the PRD Builder for a small change, with your scenario and approved Azure Boards/GitHub, SharePoint and Teams evidence.

  3. 3

    Answer its questions live. Unsure? Answer “undecided” and log it in the decision log with an owner.

  4. 4

    Run /backlog-plan read-only; write Azure Boards work items or GitHub Issues with /backlog-execute only after approval.

Tips and tricks

  • Keep it small: one feature, three to six backlog items.
  • Write at least one acceptance criterion as a concrete example: given, when, then.
  • Use your own document names and templates; ask the builders to follow them.
  • Before lunch, pick one narrow item for Exercise 5; its research can run over lunch.

Watch out

  • An agent silently resolving an open question
  • A backlog that only splits the text
  • Requirements with no version or approval stamp

Run it with

  • HVE Core: BRD Builder, then PRD Builder (they ask the clarifying questions); Backlog Manager (/backlog-plan to triage read-only, /backlog-execute for approved Azure Boards or GitHub writes); Functional Planner turns a PRD into a planned hierarchy.
  • HVE-Squad: intake gate → requirements → experiment → backlog; the Tracker-Write Gate asks a person before anything is written to the tracker.
  • Gates you exercise: Evidence → BRD (product owner) · BRD → PRD (product + engineering)

No open question was silently resolved by an agent, and every backlog item links to its evidence.

Tips

  • Use your organisation’s own document names (for example functional analysis or change-request templates) rather than forcing BRD/PRD vocabulary.
  • The key moment is step 3: the agent must stop and ask, and the product owner answers in the files, not just in the chat.
  • A business answer has to change the files (requirements, backlog, traceability), not just appear in chat.
  • Use Work IQ only for approved SharePoint/Teams source retrieval where available. A Teams message does not replace the product owner’s approval, and missing access is logged rather than bypassed.
  • Pick one narrow, testable item from this backlog for Exercise 5 before lunch; its research can run over lunch.
