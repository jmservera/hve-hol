Exercise 3 · Open lab 1 (agents can run over the break) · Parallel with a long run

Minimum viable experiments bake-off

Parallel taskOpen lab 1

On this pageBriefHow to startHand-in and toolkitTips
Objective

Use cheap experiments to decide architecture or product direction on evidence.

Input
A high-risk technical or product uncertainty
Best use
Parallel or waiting-time task
Roles (suggested)
Architect and quality lead; agents generate

Steps

  1. Name the three riskiest assumptions that could materially change the plan.

  2. Design two deliberately different minimum viable experiments (MVEs).

  3. Define success, failure and inconclusive thresholds before building.

  4. Let agents generate research or prototypes while you prepare the evaluation matrix.

  5. Compare the experiments and carry the insight into the next RPI cycle (Exercise 5).

Hand in

Tick items as your team hands them in.

Exercise 3 · How to start

Write the thresholds before the agents start

Start here

  1. 1

    Take the riskiest assumption or open question from your evidence map.

  2. 2

    Design two genuinely different MVEs, for example a read-only technical spike and a throwaway prototype.

  3. 3

    Fill both MVE cards with success, failure and inconclusive thresholds, in numbers, before any agent runs.

  4. 4

    Start two agent sessions on separate branches, one per MVE; they can keep running over the break.

Tips and tricks

  • The HVE Core Experiment Designer (opens in a new tab) agent can help you build your MVE: frame the hypothesis and plan the experiment.
  • Spike: /rpi-research for a read-only technical question. Concept: the DT Coach for a low-fidelity prototype.
  • Time-box each MVE to 20–30 minutes and prepare the decision matrix while they run.
  • No product doubt? Test a technical one: a library, an integration path, a migration approach.
  • Inconclusive is a valid result: record what would settle it and carry it into Exercise 5.

Watch out

  • Writing thresholds after seeing the output
  • Two MVEs that are variants of one idea
  • Polishing a prototype that should be thrown away

Run it with

  • HVE Core: Experiment Designer for MVE coaching; DT Coach for solution-space concepts and low-fidelity prototypes; /rpi-research for a read-only technical spike.
  • Run two agent sessions in parallel, one per MVE, on separate branches.
  • HVE-Squad: the discovery gate offers a brainstorm when nothing is written down yet; a product squad turns a business case into requirements, an experiment for the riskiest assumption and a backlog.

Example

Synthetic example (Northwind Traders, HVE-Squad workshop): a claim must reference order lines, but the order system has no API and direct database access is forbidden. MVE: 30 cases, 3 staff, paper and local only. Proposed criteria: ≥ 90% under 2 minutes; licence and run cost ≤ EUR 900 a month. Honest limit: the experiment is a plan, not a result.

Done when

Tips

  • Agents make prototypes cheap enough to throw away: build two deliberately different bets, keep the insight, discard the concept.
  • Write the thresholds before you see any agent output; otherwise you will rationalise whatever comes back.
  • No product uncertainty? Use a technical one: a library choice, an integration path, a migration approach.
  • Carry the winning insight into Exercise 5 as an explicit input to the plan.
