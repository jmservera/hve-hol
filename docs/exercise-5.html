Exercise 5 · Open lab 2 · Parallel activity

Build one reusable skill, agent or connector

Parallel taskOpen lab 2

On this pageBriefHand-in and toolkitTips
Objective

Convert local know-how into a reusable component that can connect to the wider flow.

Input
A repeated in-house method, internal agent, orchestrator or MCP pattern
Best use
Parallel or waiting-time task
Roles (suggested)
Architect and one volunteer

Steps

  1. Select one repeated task: discovery questions, Jira intake, architecture review, a code standard, AMS triage…

  2. Choose the smallest correct building block: instruction, prompt, skill, agent, hook or control, or connector.

  3. Define when it runs, its inputs, outputs, permissions and failure behaviour.

  4. Prototype the component, or write its specification.

  5. Explain where it plugs into HVE-Squad and where it should stay independent.

Hand in

Tick items as your team hands them in.

Exercise 5 · Hand-in and toolkit

Pick the smallest building block that works

If you need…→ Use…
A rule that always applies to certain filesInstruction (narrow applyTo pattern; keep it short)
A workflow someone starts on demandPrompt file or skill entry point (slash command)
Deep know-how, question banks, templates or scriptsSkill (short SKILL.md; detail in reference files)
A multi-step job with tools, phases or hand-offsAgent (restrict its tools; hand off, don’t sprawl)
A rule that must hold whatever the model thinksControl: hook, permission, schema or CI check
Governed access to Jira, Confluence, GitLab or another systemConnector (MCP server)

Tips

  • Many teams already have home-made orchestrations, agents and MCP servers; the goal is to turn one of them into something another team can safely reuse.
  • Least machinery: one well-reviewed skill beats ten private orchestrations.
  • Jira and Confluence on Data Center? Atlassian’s official remote MCP server (Rovo MCP (opens in a new tab)) is Cloud-only. The open-source sooperset/mcp-atlassian (opens in a new tab) server supports Server/Data Center but is not an Atlassian product: evaluate it under your security policy before use.
  • APM lockfile governance is stable; its policy engine (apm-policy.yml) is an early preview, so pin the APM version.
  • Further reading: Agent Skills specification (opens in a new tab) and Model Context Protocol (opens in a new tab).
