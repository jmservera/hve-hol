Exercise 6 · Open lab 3 · Core task

Execute a bounded RPI work unit

Core taskOpen lab 3

On this pageBriefHand-in and toolkitTips
Objective

Run Research → Plan → Implement → Review without losing traceability.

Input
One narrow, testable backlog item (from Exercise 4)
Best use
Core task
Roles (suggested)
Agent operator runs; product owner and architect approve the plan; quality lead reviews

Steps

  1. Agree the definition of done and the boundaries before execution.

  2. Assign the run: HVE Core, HVE-Squad or your own orchestrator.

  3. Require research and plan evidence before any implementation.

  4. While it executes, the rest of the team works on Exercise 7 and the parallel activities.

  5. Review the result against the requirement, the plan, the tests and the source evidence.

Hand in

Tick items as your team hands them in.

While Exercise 6 executes

The rest of the team starts Exercise 7 and the two intermissions for this lab.

Exercise 6 · Hand-in and toolkit

One job, one artefact and one human decision per phase

ResearchPlanImplementReview
Mayread code, docs and sources; never writes codefiles, tests, risks and rollback, then a critique (Pass · Revise · Blocked)only the approved plan; tests after each changecheck every acceptance criterion; never edits code
Leavesresearch notesplan and critiquechange log and testsreview record
You decide“Is the evidence enough?”“Approve the plan”“Do the checks pass?”“Accept, fix or follow up”

Follow-up: defects → implement · decision gaps → plan · missing evidence → research · leftovers → a new backlog item

Start it

  • HVE Core: select the RPI Agent and describe the item (manual by default; full auto only on request), or run /rpi-research, /rpi-plan, /rpi-implement and /rpi-review one at a time
  • HVE-Squad: /squad request="<backlog item>" mode=autopilot cost-ceiling=<USD> — the Implementation Gate means work never begins cold; the Impactful-Action Gate stops before deploy, push, merge or schema changes
  • Your own orchestrator: show the same four artefacts

Review language: execution status (Complete · Partial · Blocked) is recorded separately from the outcome (Conformant · Conformant with justified divergence · Defects found · Residual work · Not accepted), so “it ran” is never mistaken for “it is right”.

Done when

A named person has accepted, or sent back, the result on the basis of the review record.

Tips

  • Keep the item small enough for about an hour of implementation; if it cannot be sliced that small, it is an epic, not an exercise item.
  • Carry the Exercise 3 insight into the plan.
  • The approval of the plan is a human decision: the product owner or architect signs it, not the agent.
  • Plan IDs are stable (P01, P01-T01 …), so you can resume after clearing the chat without redoing the research.
  • If a run drifts, route the problem to the earliest responsible phase instead of patching in place.
  • For HVE-Squad, use the cost ceiling agreed for all teams and record any raise.
  • If HVE-Squad misbehaves, ask the coordinator for squad-doctor, then check the troubleshooting page; if it is still blocked, run the item with HVE Core instead.
