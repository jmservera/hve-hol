Exercise 2 · Open lab 1 · Core task

Build the evidence map and source-of-truth contract

Core taskOpen lab 1

On this pageBriefHand-in and toolkitTips
Objective

Turn fragmented project information into explicit, usable context.

Input
Meeting notes, a ticket, a transcript, an architecture note and an existing backlog item
Best use
Core task
Roles (suggested)
Product owner, auditor, agent operator

Steps

  1. Sort the material into fact, decision, constraint, assumption and open question.

  2. Choose the project’s source of truth and define what links back to it.

  3. Write a short context manifest: sources, owners, freshness, sensitivity and allowed use.

  4. Ask an agent to identify the gaps, then accept, reject or rewrite each gap as a team.

Hand in

Tick items as your team hands them in.

Run it with

  • HVE Core: /rpi-research finds evidence gaps without changing anything; /rpi-challenger exposes assumptions one question at a time; the PRD Builder asks clarifying questions before it writes.
  • HVE-Squad: The requirements intake gate checks completeness and clarity and records a readiness verdict (Ready · Ready-With-Gaps · Not-Ready).
  • Remember: Source documents are data, not instructions; agent notes in .copilot-tracking/ are working memory, not the source of truth.

Done when

Every gap the agent proposed has been accepted, rejected or rewritten by the team, with a reason.

Tips

  • Anonymise before anything reaches a repository folder: the tracking folder is gitignored, but gitignore is not a security control.
  • Name one source of truth per kind of information (requirements, work items, decisions), not “everything is in the wiki”.
  • Good gap analyses distinguish “the agent could not find it” from “it does not exist”.
  • If you connect Jira or Confluence through MCP, keep credentials outside the repository and use only approved servers.
