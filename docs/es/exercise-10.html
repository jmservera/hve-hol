Reserva · Ejercicio 10 · Tarea paralela · Hacedlo si queda tiempo

Comparad autonomía, coste y resultado aceptado

ReservaReserva

Ejercicio de reserva

Hacedlo antes del cierre solo si queda tiempo. Aparece después de la puesta en común y el cuadro de evaluación como sección de consulta, no como una franja adicional; la puesta en común sigue siendo de 17:10–17:30. Utilizad el cuadro de evaluación común.

Objetivo

Comparar la utilidad cambiando una variable, no proclamando un ganador simbólico.

Material de partida
Vuestra ejecución registrada del ejercicio 5, su commit inicial y su petición
Uso recomendado
Tarea opcional paralela o para los tiempos de espera antes del cierre
Roles (sugeridos)
Auditor / observador con el operador de agentes

Pasos

  1. Elegid una comparación: dos modelos, HVE Core frente a HVE-Squad o HVE frente a otro entorno de ejecución (vuestro propio orquestador o el modo agente de Copilot sin más).

  2. Usad el ejercicio 5 como ejecución A. La ejecución B repite el mismo elemento, petición y definición de terminado desde el mismo commit, cambiando una sola variable. Fijad la misma instantánea de fuentes autorizadas y los mismos ámbitos de acceso para ambas ejecuciones.

  3. Comparad el tiempo hasta el primer resultado útil y hasta el resultado aceptado; contad preguntas, correcciones, aprobaciones, reintentos e intervenciones no planificadas.

  4. Revisad el consumo o los indicadores de coste disponibles junto con la calidad y el retrabajo, incluidas las ejecuciones fallidas y abandonadas.

  5. Identificad una mejora reutilizable y redactad una recomendación según la fase y el contexto.

Entrega

Marca los elementos a medida que tu equipo los entregue.

Ejercicio 10 · Cómo empezar

Cambiad una cosa, medidlo todo

Empieza aquí

  1. 1

    Elegid una comparación: dos modelos, HVE Core frente a HVE-Squad o HVE frente a otro entorno de ejecución.

  2. 2

    La ejecución A suele ser la del ejercicio 5, ya registrada. La ejecución B repite el mismo elemento con ese único cambio.

  3. 3

    Iniciad la ejecución B desde el mismo commit y petición. ¿Falta tiempo? Comparad solo investigación y planificación en ambos lados.

  4. 4

    Rellenad la hoja de comparación sobre la marcha y después escribid la recomendación: fase, contexto, enfoque y motivo.

Consejos prácticos

  • Otro entorno de ejecución puede ser vuestro propio orquestador o el modo agente de GitHub Copilot sin HVE.
  • Tiempo: anotad el inicio, el primer resultado útil y el resultado aceptado. Contad todas las preguntas y correcciones.
  • Coste: consumption.md de HVE-Squad por cada tarea delegada; métricas de uso de GitHub Copilot y créditos de IA para el resto.
  • ¿Dos equipos ejecutaron enfoques distintos sobre elementos similares? Comparad entre equipos en lugar de repetir las ejecuciones.

Errores que conviene evitar

  • Cambiar a la vez el modelo y el entorno de ejecución
  • Comparar una ejecución completa con una parcial
  • Proclamar un ganador en lugar de recomendar una fase y un contexto

Mantened fijo también el contexto de Microsoft 365

Si las evidencias de SharePoint/Teams llegaron mediante Work IQ, fijad la misma instantánea de fuentes autorizadas, versiones y ámbitos de acceso para las ejecuciones A y B. Nuevos resultados de recuperación o permisos modificados son otra variable. Registrad por separado los indicadores de coste de recuperación disponibles; no deis por hecho que usar la versión preliminar de Work IQ API sea gratis.

De dónde salen las cifras

el registro del auditor · consumption.md de HVE-Squad (modelo, tokens y coste estimado por tarea delegada) y decisions.md · archivos de investigación, planificación, cambios y revisión de HVE Core · métricas de uso de GitHub Copilot y consumo de créditos de IA · Copilot Credits de Work IQ API, si se utiliza y están disponibles (mantened separadas las distintas unidades de crédito)

La comparación entre equipos es observacional

Elementos similares de equipos distintos pueden revelar patrones útiles, pero no aíslan una variable. Registrad las diferencias de alcance y contexto; no lo presentéis como una repetición controlada desde el mismo commit.

Terminado cuando

La recomendación identifica una fase y un contexto, no un ganador, y la comparación registra su variable, alcance y limitaciones.

Consejos

  • Usad registros y archivos de estado, no la memoria.
  • Los modelos más baratos pueden costar más si necesitan más ciclos; mantened fijo el entorno de ejecución al comparar modelos y fijo el modelo al comparar entornos.
  • Medid el coste por resultado aceptado, no los tokens por ejecución.
  • Reutilizad la hoja de respuestas del ejercicio 1 para comparar las decisiones humanas previstas y reales, y el registro de modificaciones del PO de la actividad de espera A.
