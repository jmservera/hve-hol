Ejercicio 6 · Laboratorio abierto 3 · Tarea paralela · Tras la primera ejecución RPI

Reutilizad lo aprendido en la primera ejecución RPI

Tarea en paraleloLaboratorio abierto 3

En esta páginaResumenCómo empezarEntrega y herramientasConsejos
Objetivo

Capturar una lección del ejercicio 5 como instrucción, habilidad o control que utilice la siguiente ejecución.

Material de partida
Correcciones y hallazgos de revisión del ejercicio 5, más el registro del auditor
Uso recomendado
Tarea paralela, cuando el ejercicio 5 ya tenga una revisión
Roles (sugeridos)
Arquitecto y una persona voluntaria

Pasos

  1. Buscad algo que tuvisteis que corregir, repetir o explicar al agente en el ejercicio 5.

  2. Elegid el componente más pequeño: archivo de instrucciones, instrucción de alcance limitado, prompt, habilidad, hook o conector.

  3. Definid cuándo se ejecuta, sus entradas, salidas, permisos y comportamiento ante fallos.

  4. Construidlo con hve-builder y repetid un paso RPI para comprobar que la corrección ya no hace falta.

  5. Explicad dónde se integra con HVE-Squad y dónde debe mantenerse independiente.

Entrega

Marca los elementos a medida que tu equipo los entregue.

Ejercicio 6 · Cómo empezar

Conseguid que la siguiente ejecución necesite menos correcciones

Empieza aquí

  1. 1

    Leed el registro del auditor y la revisión del ejercicio 5: ¿qué corregisteis, repetisteis o explicasteis al agente?

  2. 2

    Elegid una lección que se repetirá: una convención, cómo ejecutar vuestras pruebas, una plantilla o una lista de comprobación para la clasificación inicial.

  3. 3

    Elegid el componente más pequeño: una línea en .github/copilot-instructions.md, una instrucción de alcance limitado o una habilidad.

  4. 4

    Creadlo y validadlo con hve-builder; después, repetid un paso, como /rpi-plan, y comprobad que la solución se mantiene.

Consejos prácticos

  • ¿Una regla para todo el repositorio? copilot-instructions.md. ¿Una regla para algunos archivos? Una instrucción con un applyTo acotado.
  • ¿Conocimiento práctico, listas de comprobación o plantillas? Una habilidad: un SKILL.md breve con el detalle en archivos de referencia.
  • ¿Una regla que debe cumplirse siempre? Un hook o una comprobación de CI (ejercicio 7), no más instrucciones.
  • Asignad responsable y versión para que otro equipo pueda instalarlo.

Errores que conviene evitar

  • Consejos genéricos como «escribe código limpio»
  • Un agente grande cuando bastaría una línea de instrucción
  • No comprobar nunca si cambia la siguiente ejecución

Ejecútalo con

La habilidad hve-builder de HVE Core (crear, validar, revisar con dictamen de aprobado / revisar / bloqueado y corregir). Empaquetadla y fijad su versión con APM: un manifiesto, un archivo de bloqueo de dependencias y una directiva de organización sobre qué puede instalarse.

Terminado cuando

Alguien ajeno al equipo podría instalarlo y ejecutarlo solo con la especificación, y la repetición de un paso RPI demuestra que la corrección original ya no hace falta.

Consejos

  • Partid de una corrección observada, no de una idea genérica de componente. La prueba es el cambio de comportamiento en la siguiente ejecución, no el tamaño de la especificación.
  • Menos complejidad: una habilidad bien revisada es mejor que diez orquestaciones privadas.
  • Reutilizad Azure DevOps MCP (se abre en una pestaña nueva) o GitHub MCP server (se abre en una pestaña nueva) autorizados para el contexto de entrega. Work IQ (se abre en una pestaña nueva) opcional recupera evidencias autorizadas de SharePoint/Teams; no sustituye la aprobación para escribir en el sistema de seguimiento.
  • Incluid el acceso a fuentes, las herramientas permitidas y el comportamiento ante fallos en la especificación del componente. No incrustéis extractos privados de Microsoft 365 ni credenciales en una habilidad pública reutilizable.
  • El gobierno del archivo de bloqueo de APM es estable; su motor de directivas (apm-policy.yml) está en una fase preliminar temprana, así que fijad la versión de APM.
  • Lecturas adicionales: Especificación de Agent Skills (se abre en una pestaña nueva) y Model Context Protocol (se abre en una pestaña nueva).
