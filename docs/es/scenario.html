Tu caso

Traed un cambio pequeño y real, o utilizad un caso preparado

Un buen caso…

  • Es real, pequeño y acotado: un cambio que podáis terminar hoy o planificar de forma creíble
  • Está anonimizado o simplificado si contiene información sensible
  • Tiene un responsable en el equipo que puede responder a las preguntas
  • Cuenta con una definición de terminado sencilla y al menos una prueba de aceptación representativa

Casos habituales

Cambio en un sistema existente

petición de servicio → investigación de la aplicación → cambio acotado → revisión de regresión

Corrección de dependencias o de seguridad

evaluar el paquete, las interfaces, las pruebas y la reversión

Parte acotada de una modernización

p. ej., de .NET Framework a .NET actual o una actualización de Java; primero, las pruebas que faltan

Clasificación inicial de incidentes

priorizar hipótesis a partir de registros y contexto, validar la corrección y actualizar el manual operativo

Una pequeña funcionalidad de nueva creación
