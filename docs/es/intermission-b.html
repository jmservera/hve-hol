Actividad de espera B · Mientras se ejecuta el ejercicio 5 · Laboratorio abierto 3 · Tarea paralela

Cerrad el ciclo: de Azure Boards o una issue de GitHub al parche

Tarea para los tiempos de esperaLaboratorio abierto 3

En esta páginaResumenEntrega y herramientasConsejos
Objetivo

Dirigir hallazgos de Azure SRE Agent o incidencias de Azure Boards/GitHub a un flujo automatizado de parches fundamentado en conocimiento.

Material de partida
Un elemento de trabajo de Azure Boards o una issue de GitHub, los artefactos disponibles del ej. 5, instrucciones, habilidades, ADR y contexto opcional de manuales operativos autorizados de Microsoft 365
Uso recomendado
Tarea para los tiempos de espera durante el ej. 5
Roles (sugeridos)
Operador de agentes y arquitecto; el responsable de calidad asume el punto de aprobación humana

Pasos

  1. Elegid tres elementos de trabajo de Azure Boards o issues de GitHub, por ejemplo registros de hallazgos de Azure SRE Agent.

  2. Esbozad un flujo de una etiqueta de issue de GitHub a Actions, o un hook de servicio de Azure Boards más un despachador autorizado que ponga en cola una ejecución de Azure Pipeline.

  3. Fundamentad cada parche en instrucciones, habilidades, ADR y contexto de entrega. Cuando esté autorizado, utilizad herramientas de lectura de Work IQ para manuales operativos de SharePoint y notas de incidentes de Teams, con citas de las fuentes.

  4. El agente abre una pull request en borrador con el parche, las pruebas y el enlace a la issue; una persona revisa, nunca se hace merge automático.

  5. Devolved el resultado al ciclo: cerrar, reabrir o convertir el fallo en una nueva instrucción o habilidad.

Entrega

Marca los elementos a medida que tu equipo los entregue.

Herramientas para realizarlo

Copilot CLI o un cliente con MCP autorizado para el taller · integraciones de lectura de Azure DevOps/GitHub · herramientas de lectura opcionales de Work IQ para evidencias autorizadas de SharePoint/Teams · accelerators.ms · GitHub Actions o Azure Pipelines con un despachador de eventos y un ejecutor de agentes autorizados

Reglas

  • La recopilación de fuentes utiliza solo herramientas de lectura y datos autorizados del taller; conservad las citas y las restricciones de acceso
  • Las escrituras de elementos de trabajo y PR requieren un permiso/una aprobación independiente; solo PR en borrador, una persona hace el merge
  • Si la recuperación con Work IQ no está disponible o se deniega, se detiene; utilizad extractos ficticios autorizados, nunca eludáis las directivas

Consejos

  • Los equipos que usan GitHub utilizan un flujo agéntico o Actions para entregar las issues etiquetadas al agente de programación de Copilot.
  • Para Azure Boards, utilizad un hook de servicio y automatización/un despachador autorizado para poner una canalización en cola. No deis por hecho que la actualización de un elemento de trabajo sea un desencadenador nativo de una canalización YAML.
  • Aquí el acceso a fuentes mediante Work IQ es opcional y de solo lectura. Si no está disponible, usad extractos autorizados de manuales/notas y registrad la ausencia de conexión real; no eludáis las directivas.
  • Mantened el ciclo acotado: solo PR en borrador, un límite de reintentos y merge humano.
  • La entrada puede representar un hallazgo de Azure SRE Agent o una petición de soporte; no deis por hecho que haya una integración automática configurada. Las escrituras de elementos de trabajo y PR en borrador requieren una aprobación independiente.
  • El diagrama del ciclo sirve para el ejercicio 7 (aprobaciones y controles).
