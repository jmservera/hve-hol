Your scenario

Bring a small, real change, or use a ready-made one

A good scenario is…

  • Real, small and bounded: one change you can finish, or credibly plan, today
  • Anonymised or simplified if it contains sensitive information
  • Owned by someone in the team who can answer questions
  • Has a simple definition of done and at least one representative acceptance test

Typical scenarios

Change to an existing system

service request → application research → bounded change → regression review

Dependency or security remediation

assess the package, interfaces, tests and rollback

Modernisation slice

e.g. .NET Framework to current .NET or a Java upgrade, missing tests first

Incident triage

rank hypotheses from logs and context, validate the fix, update the runbook
